The existing phase2 failed to repair one source-required tail despite complete
feedback, correct pending-actor targeting, fresh normal rosters and completed
known-usage responses. Strict admission correctly rejected it. The original
closed job, submitted sources, drafts, receipts and public/lock evidence stay
unchanged. No numerical value is repaired, clamped, invented or auto-declined.

Luna primary remains low. Only its existing correction requests use medium;
the configured stronger model remains low. Model, tier, seven-thousand total
output cap, retry allowance, receipt bound, two phases, two logical day-of slots,
lease/deadline, provider cadence and all wallet controls remain unchanged.
Primary transport stays byte-exact for the same request body; correction
transport differs only in explicit reasoning metadata, apart from the new
immutable generation label. Count requests and full source/schema/feedback are
unchanged. Earlier releases retain their original low-effort request parser.

Official OpenAI documentation confirms Luna supports medium (its documented
default), while reasoning effort trades additional model work for token/latency
cost. The cap includes both reasoning and visible output; an incomplete answer
may consume the cap without usable text. No new cap or inference call is added.
Sources: https://developers.openai.com/api/docs/models/gpt-6-luna and
https://developers.openai.com/api/docs/guides/reasoning (read November26 Eastern).

No same-outcome fit, new grade rule or probability calibration is introduced.
Same accepted laws have identical prices/projections/grades/stakes and board
counts: promoted0/demoted0/net0. Increased actual correction usage is possible
inside the already-reserved maximum; monthly coverage/cost is not guaranteed.

correction success and predictive-accuracy claims remain unproved. Only normal
scheduled future production may supply that evidence; no paid proof is bought.

known-receipt sibling retention, low primary/stronger transport, medium Luna
