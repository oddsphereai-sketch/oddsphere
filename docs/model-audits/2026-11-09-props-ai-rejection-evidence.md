## Confirmed weaknesses

The physical validator stopped at the first player/scenario and produced a generic
message. Independent synthetic eight-player cases show that one opaque finding
does not identify the other actors/scenarios needing the existing correction.
Future R20 preflight collects every physical violation without changing a law.
Compact feedback retains every actor and failed identity rule, then example
scenario values as space permits. Exact full findings stay in private evidence.
The existing R1 validator and source checks remain authoritative; declining a
player requires the existing explicit gap and every-market exception contract.

A rejected billed draft previously received an immutable usage receipt before
validation, without its exact input/draft or validation reason. Future receipts
are built once after parsing, with actual billing preserved regardless of outcome.
Failure-only exact part/request/draft text is gzip encoded with byte lengths and
SHA-256 hashes. Authorization headers are never serialized. Each raw artifact
has existing-size-style bounds and the complete evidence has a 768KB JSON bound;
if archival construction cannot fit, an explicit archive-unavailable marker keeps
the reason/findings and billing still settles. These private records are never
added to accepted member evidence, public pages or console logs.

Ordinary HTTP 429 errors previously lost their code/type before persistence.
Future transport captures bounded allowlisted metadata: HTTP status, error
code/type, request ID, Retry-After and documented rate-limit header values. Error
bodies are bounded during stream reading, rather than checked only after complete
allocation. Raw error messages, arbitrary headers and authentication are excluded.
Normal successful responses also retain header evidence for later capacity audit.

## Billing and scheduling boundaries

Ordinary 429 retains an unknown charge reservation and is not retried. Existing
explicit Flex resource-unavailable rejection remains the sole affirmative
uncharged HTTP classification. Billed invalid output can use only the existing
wallet-authorized second phase; successful parts are not repeated. No new slot,
third phase, request/output cap, concurrency, writer, provider call, stronger quota
or spending-limit increase is introduced. Legacy locks and closed jobs stay exact.

A local semaphore bounds concurrency but does not pace starts or coordinate
account traffic across sports/apps. This release records missing evidence; it
does not claim to solve that admission problem or restore exhausted quota. A
future pacing change needs actual capacity evidence, deadline/queue accounting,
shared admission and independent offline tests before deployment. Retrying an
unknown charge or weakening physical checks is not an acceptable workaround.

OpenAI distinguishes temporary rate errors from billing/quota failures, and
provides request/token limit and reset headers. See [error codes](https://developers.openai.com/api/docs/guides/error-codes)
and [rate limits](https://developers.openai.com/api/docs/guides/rate-limits).
