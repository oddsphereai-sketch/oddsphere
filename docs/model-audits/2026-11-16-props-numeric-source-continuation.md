# Canonical source navigation and bounded correction continuation

## Problem and resulting behavior

The NFL source packet contained the raw statistics, but did not include the
compiled per-market numeric admission envelopes provided by NBA navigation.
A correction also included only unhandled findings: valid explicit declines of
unsupported statistics were lost when the independent second request regenerated
the full part. Finally the instructions suggested a prose role adjustment could
justify an out-of-envelope mean although admission has no such waiver.

R43 exposes the existing numeric contract for NFL/MLB and explains canonical
means versus generative components. A correction retains source-validated
unsupported-market declines; it still returns every player/market and repairs
supported scopes. It does not copy an old law, force a forecast or modify admission.
The original correction function remains available with its original semantics.

## Safety and impact

Only future requests use the new release. All R42 and earlier accepted readers
remain explicit. Law mathematics, source envelopes, actual quote qualification,
grades, stakes, context checks and first-lock precedence are unchanged. There is
no new writer, lease, review slot, phase, model, output cap, provider call, spending
limit, automatic decline, range clamp or historical repair. Exact input token
counting and funding include the new navigation before normal generation.

There is no deterministic board demotion rule: existing accepted laws yield the
same numerical board. Synthetic real-reviewer controls recover three supported
QB scopes while declining two unavailable scopes, and reject both out-of-range
means and reopened unsupported markets. Existing valid Over/Under, rare-event,
signed yardage, derived-market and exact legacy-lock controls remain mandatory.
A future model response may still fail; deployment and clean offline reviews
are not proof of predictive accuracy or future completion.

## Verification

The focused source-continuation test blocks real network and runs both phases
through the production reviewer with synthetic HTTP responses and known receipts.
It checks exact envelopes, all actor/market entries, original input equality,
complete corrective constraints, decline continuation, unsafe-reason rejection,
1,984-byte fail-closed overflow, MLB rare-event opportunities and R42 membership.
Required full model, affected focused, TypeScript, lint, build, hosted disposable
PostgreSQL and integration checks plus two consecutive fresh triple-review rounds
must pass on the unchanged final candidate before protected publication. Live
verification uses only ordinary scheduled production requests and separate actual
member/lock observations; no paid proof or replay is authorized.
